# Catalog probe — 2026-08-06

LoaderBridge queried the official Modrinth and CurseForge APIs with a local,
non-exported CurseForge credential and froze a temporary 1,000-project Fabric
1.21.1 snapshot. The credential was read only from the ignored
`.loaderbridge-secrets.env` file and was not written into the snapshot, logs,
locks, or Git.

The first full attempt exposed CurseForge file `8287094` under project
`448233`, whose `/download-url` route returns HTTP 403 because third-party
distribution is unavailable. The provider now treats only 403/404 from that
specific fallback route as an ineligible artifact and continues catalog top-up.
Other API authorization failures remain fatal.

Transient timeouts and connection resets also exposed the need for an explicit
transport classification. Repository transports now distinguish retryable
send/body failures from policy, HTTP, parsing, and validation failures. The
collector retries the typed transient class exactly three times. Metadata
attempts are capped at 30 seconds; artifact downloads retain a five-minute
bound.

Four resolution workers process each 50-project page while results are joined
in original platform rank order. A 100-project probe fell from roughly four
minutes to about one minute. Sequential and parallel runs selected identical
projects and artifacts; only live CurseForge download counters changed between
requests.
